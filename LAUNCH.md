# Putting Glovels online — the exact steps

About twenty minutes, most of it waiting. Two free accounts to create (GitHub and
Render) and one card to add (Render's Starter instance is **$7/month**, plus **$0.25/month**
for the 1 GB disk).

Everything Render needs is already in this folder — `render.yaml` describes the whole
service, so you are clicking Approve rather than filling in forms.

> **Why not Vercel or Cloudflare?** Both throw away the filesystem between requests, and
> this application keeps its database and every uploaded passport scan as files on disk.
> Vercel's own documentation says SQLite cannot be used there; Cloudflare's says *"All disk
> is ephemeral. When a Container instance goes to sleep, the next time it is started, it
> will have a fresh disk."* Either would lose every student account on every deploy.
> `DEPLOY.md` has the longer version.

---

## 1 · Put the code on GitHub

Create the account first if you do not have one: <https://github.com/signup>.

Then, on <https://github.com/new>:

- **Repository name:** `glovels`
- **Private** — this is your business's site, and `render.yaml` names your infrastructure
- Do **not** tick "Add a README", "Add .gitignore" or "Choose a license"

GitHub then shows a page of commands. Ignore it and use these instead, in Terminal
(open Spotlight with ⌘-Space, type `Terminal`). Replace `YOUR-USERNAME`:

```bash
cd ~/Downloads/build
git init
git add .
git commit -m "Glovels — site, student portal and operations site"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/glovels.git
git push -u origin main
```

It will ask for your GitHub username and password. **The password is not your GitHub
password** — GitHub stopped accepting those. Create a token at
<https://github.com/settings/tokens> → *Generate new token (classic)* → tick **repo** →
Generate → copy it, and paste that as the password.

**Check before you push:** `git status` should not list `data/` or `mail.env`. `.gitignore`
excludes both. Student records and your mail password must never enter a git history,
because a git history is permanent even after a delete.

## 2 · Create the service on Render

1. Sign up at <https://dashboard.render.com/register> — choose **GitHub** so it can see
   the repository.
2. **New +** → **Blueprint**.
3. Pick the `glovels` repository. Render finds `render.yaml` and shows one web service
   with a 1 GB disk attached.
4. It asks for two values:
   - **ADMIN_EMAIL** — the address you will sign in with, e.g. `you@glovels.com`
   - **ADMIN_NAME** — your name, e.g. `Vishal`
5. **Apply**. The first deploy takes two or three minutes.

Your address will be something like `https://glovels.onrender.com`. Render sets it, and the
server reads it — password-reset links and order emails come out with the right domain
without you configuring anything.

---

## 3 · Get your password and sign in

The admin password was generated by Render and never typed by anyone, which is the point.

**Dashboard → glovels → Environment → `ADMIN_PASSWORD` → the eye icon.** Copy it into your
password manager now.

Then open `https://your-address.onrender.com/login` and sign in with that and your
ADMIN_EMAIL. You land on the **Organisation** screen.

**There are no demo accounts.** On your laptop the server creates three with the password
from the README; in production it refuses to, and it refuses to start at all if you try. So
the site starts as one administrator — you — and nobody else.

---

## 4 · Add your team

On **Organisation → The team → + Add someone**, for each person:

| They need to | Give them |
|---|---|
| Answer students and run the chat | **Counsellor** |
| Only change the home page and the universities | **Website editor** |
| Everything, including adding people | **Administrator** |

Then tick what they may change on the website:

- **Home page** — packages, prices, the figures, the questions, the stories, the wording
- **Universities** — adding, editing and removing what the finder offers

A counsellor gets neither by default. A **website editor** never sees a student record, a
document or a conversation — it is the account for whoever writes the copy or keeps the
university list current, and the safest permission is the one that was never granted.

**The password is shown once.** It is stored hashed, so it cannot be read back — copy it,
send it to them, and if it is lost use *Reset password* beside their name.

---

## 5 · Before you tell anyone the address

**`robots.txt` currently blocks every search engine** (`Disallow: /`). That is correct while
you are testing. Nothing will be indexed until you edit that file, so there is no rush and
no accident.

Two things to do straight away:

1. **Sign in as each person you invited** and check they see what you meant them to see.
2. **Confirm the ten DUMMY figures** on the Home page screen, or leave the DUMMY markers
   showing — they are deliberately ugly so an unverified student count cannot ship quietly.

And one to be aware of: **no payment is taken.** An order is recorded, the receipt goes out
and the universities unlock, but no gateway is connected. Do not put the address in front
of a paying customer until one is.

## 6 · Email (do this before you send anything real)

Until it is set up, every message the site sends is written into `/data/outbox/` as a file
instead. Nothing is lost — nothing arrives either.

**one.com will not work from Render.** They only accept SMTP from sites hosted with them.
Use a transactional provider — Postmark, Resend, Brevo or SES — keep `info@glovels.com` as
the address the mail comes *from*, and publish the SPF and DKIM records they give you.

Then in **Render → Environment**, add:

```
SMTP_HOST     smtp.postmarkapp.com      (whatever the provider gives you)
SMTP_PORT     587
SMTP_USER     …
SMTP_PASS     …
MAIL_FROM     Glovels <website@glovels.com>
MAIL_TO       info@glovels.com
```

---

## 7 · Your own domain

Once you are happy with it, in **Render → Settings → Custom Domains** add
`app.glovels.com` (a subdomain — the main site is still on Wix). Render gives you a CNAME
to create at your DNS host, and issues the HTTPS certificate itself.

Then add **`GLOVELS_URL = https://app.glovels.com`** in Environment, so links in emails
point at your domain rather than at `onrender.com`.

While you are in DNS, two things are wrong today and worth fixing:

- **`glovels.com` and `www.glovels.com` point to different places** — the nameservers are
  Wix, `www` resolves to Wix and the apex to one.com. Pick one and redirect the other.
- **The DMARC record is on the apex, where it does nothing.** It belongs at
  `_dmarc.glovels.com`. There is no DKIM record at all.

## Making a change later

Edit the files, then:

```bash
cd ~/Downloads/build
git add .
git commit -m "what you changed"
git push
```

Render notices the push and redeploys by itself. **The disk survives** — accounts,
documents, messages and everything edited on the Home page screen are on `/data`, not in
the code. There is a short gap during a deploy (two deployments cannot hold the same disk
at once), which is why it is worth doing outside office hours.

Content changes do **not** need a deploy. Prices, packages, wording, universities — all of
it is edited in the operations site and live on the next page load.

## When something is wrong

| What you see | What it is |
|---|---|
| Deploy fails, log says a setting is missing | Production refuses to start unsafely. The log names the exact variable. |
| Blank white page | Look at **Logs** in the Render dashboard — the error is there, in English. |
| Sign-in says the password is wrong | The generated one has characters that are easy to mistype. Copy it, do not retype it. |
| Everything logged out after a deploy | Sessions are in the database on `/data`. If they are gone, the disk is not mounted — check **Disks** shows `glovels-data` at `/data`. |
| A counsellor sees "Not your workspace" | They are an editor, or lack that permission. Organisation → tick the box. |

**Back up `/data`.** It is the only copy of every student record. Render can snapshot the
disk; set it up before there is anything on it worth losing.
